# 《公共课设计规划》审阅与补充要求

## 审阅结论

《公共课设计规划》已经给出了较明确的视觉基准，包括主色、字体、圆角、阴影、侧栏、顶部栏、部分课程/考试/背单词/教师看板页面的基本布局。它可以作为视觉语言的候选方向，但目前不能单独作为整站 UI/UX 实施依据。

主要问题不在于视觉风格，而在于范围与业务交互描述不足。方案只详细描述了登录、登记/考试、学生首页、课程列表、自测、背单词、选择题、难题讲解、教师看板、学员管理、课程商品、机器人、系统设置等少部分页面；原有全站设计文档中要求的计划、学习工具总览、自测档案、商城订单、社区、账户资料、教师复习规划、应用管理、带背后台、题库试卷、知识库、社区审核、订单权益、审计和备份等功能没有对应的可实施页面说明。

以下内容已经按现有系统规则直接推演，不需要再由产品方确认。本文末尾只保留会影响产品决策的少数确认项。

## 一、可以保留的设计方向

以下设计方向可以保留，并作为后续全站设计统一使用的基础。

| 项目 | 可保留内容 | 落地要求 |
| --- | --- | --- |
| 总体风格 | 清晰、克制、结构化、轻量 Apple 风格 | 不要变成营销落地页；教师端保持高信息密度，学生端保持连续学习感。 |
| 页面底色 | `#F5F5F7` | 大面积内容区仍须靠分区、边框和留白建立层级，不能所有内容都悬浮成卡片。 |
| 文字色 | `#1D1D1F`、`#86868B`、`#C7C7CC` | 必须补充正文、次要文字、禁用文字的对比度校验。 |
| 品牌色 | `#0071E3` | 主按钮、焦点、链接、进度、选中态需统一，危险操作不可使用品牌蓝。 |
| 状态色 | 成功绿、错误红、警告橙 | 状态不可只用颜色；必须同时有图标和文字。 |
| 学科色 | 政治紫、英语绿、数学橙 | 只用于科目识别、细色条、标签和图表；不得用大面积背景制造视觉噪声。 |
| 字体 | 系统字体 + 苹方回退 | Windows 环境必须有可靠的中文回退；表格数值和日期使用等宽数字。 |
| 圆角与阴影 | 8px/12px 圆角、低层级阴影 | 页面主区块不要卡片嵌套；重复项、弹窗、工具面板可以使用卡片。 |
| 响应式 | 桌面工作台 + 移动单列 | 学生端和教师端不能共用同一套压缩策略，详见后文。 |

## 二、必须修正的基础规范矛盾

### 2.1 “所有尺寸为 8 的倍数”与文档自身冲突

原方案声明所有间距与尺寸必须是 8 的倍数，但同时使用了 12px、20px、24px、32px、40px、44px、50px、56px、72px、83px、120px、140px 等多种数值。其中 12、20、40、44、50、56、72、83、120、140 并非 8 的倍数。

无需确认，建议改为以下规则：使用 4px 基准网格；空间优先使用 4、8、12、16、20、24、32、40、48、56、64；控件高度可使用 32、36、40、44、48、52、56；不要求所有文字字号与设备安全区高度为 8 的倍数。

### 2.2 “只允许六种字体大小”不可执行

原方案限定只使用 H1/H2/H3/Body/Caption/Number 六种字号，但正文中已包含 10px、12px、13px、14px、15px、16px、17px、20px、22px、32px、34px、48px。这会让工程师无法判断哪些才是合法值。

无需确认，建议改为一个可实现的中文排版比例：10px（极小辅助）、12px（说明/标签）、13px（表格辅助）、14px（正文）、15px（表单和内容强调）、16px（题干/关键正文）、17px（卡片标题）、20px（模块标题）、24px（页面标题）、32px（桌面首页大标题）、36px（重要数字）。在移动端将大标题收敛到 24px，避免挤压任务与操作区域。

### 2.3 Apple 风格不等于全面玻璃拟态

原方案要求侧栏和 Popover 大面积使用模糊透明背景。该效果可保留在顶栏、账户菜单和轻浮层，但教师端表格、长列表、题库编辑和表单配置区域不应以模糊背景为主，否则会损失可读性并增加渲染成本。

无需确认，建议：主内容区和数据表格使用不透明白色/浅灰背景；仅在悬浮菜单、移动端底部栏、轻量顶部栏使用透明模糊；支持 `prefers-reduced-transparency` 或在低性能设备回退为实色。

### 2.4 API Key 的描述必须删除并替换

原方案在监管机器人表单中写了“API Key：显示为掩码，右侧测试连接按钮”。这不符合当前平台安全边界。浏览器和 React 状态不应接收、保存、展示或修改真实 API Key。

无需确认，必须改为：界面展示 `secretRef`（服务端密钥引用名）、密钥状态（未配置/已配置/不可用）、最近测试时间、测试结果和配置影响范围；“测试连接”请求只由服务端执行。不能设计 API Key 输入框、复制按钮、查看明文按钮或前端掩码值。

## 三、现有页面中需要补清的交互

### 3.1 登录、注册与独立链接页面

原方案只描述了登录的左右分屏和基本输入框。需要补充以下状态：学生登录、教师/管理员登录、学生注册、首次强制改密、账号停用、登录超时、错误角色入口、网络失败、服务器失败、提交中、成功后的返回路径。

学生端与教师端入口应明确隔离：学生在教师入口登录时提示前往学生端；教师在学生入口登录时提示前往教师端。已被管理员重置密码的账号必须进入强制改密页，不能跳过直接进入系统。

公共登记、资料采集和入学考试必须分别设计：加载中、链接无效、链接过期、无权访问、重复提交、提交成功、提交失败、联系老师。资料采集页与考试页不能共用“剩余时间”顶部栏；只有考试页才显示倒计时。

### 3.2 学生首页

原方案只画出了“倒计时 + 今日进度环 + 今日任务列表”。还需补充：休息日状态、日/周/月自测入口、今日完成任务、学习回顾、未来 7 天入口、目标分、任务为空的不同原因、任务实际完成情况填写入口。

任务列表必须区分三种内容：新的当前任务、从前一天顺延的未完成任务、同一任务行中尚未完成的分项。多分项任务需显示“4/5 已完成”；一项工具学习完成不能自动等同于计划任务完成。

主页的进度环只能表示计划任务完成率或今日学习安排完成率，不能混合课程进度、词书进度和题目进度。其标题和计算范围必须写清楚。

### 3.3 课程页

原方案只描述课程卡片。还需设计课程详情和学习播放页：课程简介、目录、当前章节、已完成章节、资料下载/阅读、无观看权限、课程下架、播放加载、视频失败、继续学习、课程为空、未报名课程的购买/申请路径。

课程不能仅显示“课程卡片”；学生需要明确看出公开课、已报名科目课程和未开通课程的差异。未开通不应显示为错误，也不能让学生误以为可直接播放。

### 3.4 商城和订单

原方案遗漏整个商城/购买申请流程。必须增加商品列表、商品详情、申请/下单确认、订单列表、订单详情、待审核、已通过、已拒绝、补充材料、开通中、已开通、开通失败和全局免费开放状态。

订单审核前不展示“课程已开通”。订单通过后，明确提供“进入课程”；若只是提交申请，则只提供查看订单状态、取消申请或补充材料等真实操作。

### 3.5 自测、自测结果与自测档案

原方案有自测入口和答题页，但缺少结果页与档案页。必须补充分数、得分率、已答/未答、错题、解析、知识点分布、教师批注、AI 建议、加入复习、历史筛选和详情页。

自测的“标记待复查”功能只有当后端或本地数据模型能保存该标记时才能实现；在未支持前，设计中应标为可选 UI，不要将其当作已实现功能。提交失败必须保留未提交答案并支持重试，但不能把草稿写成已提交成绩。

### 3.6 背单词页面的业务流程必须更正

原方案把操作写成“不认识 / 认识”，且两个按钮位于单词卡底部并在点击后直接切换下一张卡。这与平台确认的学习规则不一致。

无需确认，应该设计为三个稳定操作，且按钮不因释义出现而移动：

1. “认识 · 查看释义”：点击后才在固定预留区域显示中文释义、例句/记忆助剂。
2. “已掌握并进入下一个”：仅在已查看释义后可用；点击后才记录为正常学习完成并进入下一词。
3. “暂不掌握，下一词”：不计完成，保留当前进度位置逻辑。

桌面端需要在一屏内完成一次单词判断。释义区域必须预留固定高度，不能因展开将按钮推向下方。按钮可垂直排列在右侧操作栏，也可在底部按清晰主次层级排列；应优先采用右侧竖排以避免单屏高度不足。卡片切换动画应低调，使用淡入淡出或横向过渡，不要强制“整体上滑 + 新卡从下方滑入”，以免制造页面跳动和眩晕。

必须补充词书选择页、已学习/剩余/昨日完成、继续学习、复习昨日、词书为空、释义缺失、发音失败、服务未配置、全部学习完成等状态。

### 3.7 政治/英语选择题

原方案只写了题干和选项颜色。还需补充题库选择页、进度、提交前、提交后、正确答案、解析、下一题、题库完成、昨日复习、题库为空和解析失败。

正确答案不能在提交前显示。仅当学生提交答案并看见结果后，题目才计入正常学习完成；“复习昨日”只复习昨日完成题目，不增加新学习进度，也不推进下一个学习位置。

### 3.8 代学/限时学习

原方案完全遗漏。必须设计题库入口、倒计时、题目与答案区域、提前结束二次确认、时间结束、答案/分析展开、完成记录、昨日复习、断网、恢复会话、会话已失效等。

计时结束或用户提前结束并打开答案/分析后，题目才算完成。不能在点击开始或仅浏览题目时记录完成。

### 3.9 难题逐步讲解

上传区和结果区已有基本说明，但要增加选择科目、补充说明、图片预览、删除图片、格式/大小限制、识别中、生成中、服务未配置、识别失败、生成失败、重试和结果可信边界。

结果须按固定结构展示：审题、考点与方法、分步推导/作答、最终答案、易错点与复查。任何模拟或本地草案必须显式标为“演示/草案”，不能显示为真实 AI 返回。

### 3.10 学习计划、学习工具总览、社区和账户资料

原方案遗漏四个学生端重要页面。

学习计划：今日、未来 7 天、全部计划、计划详情、任务行、完成历史、顺延提示、实际完成情况、教师锁定说明和申请调整入口。

学习工具总览：不是静态图标宫格。每个工具显示当前进度、剩余、昨日可复习、最近使用时间、访问状态和“继续学习/开始学习/复习昨日”。

社区：帖子流、搜索、标签筛选、发帖、附件、审核中/公开/驳回/需修改、帖子详情、评论、点赞/收藏、举报和个人发布记录。

账户资料：通过头像菜单进入，不应重复放到学生桌面侧栏；包含个人资料、密码、目标信息、科目目标分、休息日、自测推送偏好、收货信息和隐私敏感字段掩码。

## 四、教师端缺失页面与交互

### 4.1 数据看板

保留指标卡和风险学生表格。补充每个指标的统计区间、更新时间、数据来源、加载失败状态和点击后的筛选跳转。任何指标加载失败不能显示伪造的 0。

待审核登记、待审订单、待审社区内容和待确认 AI 结果应作为可点击待办区，而不是仅放入一张总览卡。

### 4.2 学员管理和详情

学员管理应补充搜索、筛选、排序、分页/加载更多、批量操作、创建学员、导入登记、停用、恢复、重置密码、操作影响说明和操作记录。

学员详情应明确为“概览 + 标签页”，至少有：基础档案、学习概览、学习计划、自测、错题与薄弱点、课程权限、AI 建议、操作记录。原方案仅写基础档案双列是不够的。

在学生详情中，未来 30 天 AI 学习智能检测必须作为计划列表末尾的建议区；教师可采纳、修改、忽略，并记录人工决定。AI 不能直接改写完整计划。

### 4.3 复习规划

原方案遗漏。必须设计计划模板列表、模板编辑、版本、草稿/发布、适用学科、任务行、分项任务、预计时长、前置关系、分配学生、开始日期、学生计划副本预览、一对一调整和调整历史。

模板发布后学生使用的是计划副本。修改模板必须产生新版本，不能回写既有学生计划；设计稿需要明确“编辑模板”和“调整某学生计划”的不同入口与影响范围。

### 4.4 课程与商品

原方案只有列表视图，需补充课程详情/编辑、章节编辑、媒体上传与转码、发布前检查、发布/下架影响提示、商品编辑、商品上下架、订单审核、权益开通和订单详情。

课程与商品负责课程、媒体、商品和课程权益，不负责词书、普通工具题库或学生工具学习进度。

### 4.5 应用管理

原方案遗漏。该模块负责英语词书、政治选择题、英语选择题、工具封面/说明、工具排序、可见范围、启用状态和默认学习规则。

词书编辑需包含单词、音标、中文释义、发音资源、例句/助记；选择题编辑需包含题干、选项、答案、解析、标签、难度、知识点、发布状态。修改已发布内容时需提示对正在学习、昨日复习和历史记录的影响。

### 4.6 带背后台

原方案遗漏。该模块负责代学/限时学习题库、题目、答案解析、计时规则、顺序、适用科目、启用状态和会话边界；不负责普通词书和政治/英语连续刷题题库。

编辑时需要提示会否影响正在进行的计时会话；下架不应删除历史学习记录。

### 4.7 自测、题库与试卷

原方案只停留在学生答题效果，没有教师端试卷管理链路。必须补充题库列表、题目编辑、来源、难度、标签、版本、AI 草稿审核、试卷组卷、预览、分发、开始/截止限制、学生作答状态、客观题评分、主观题批改、发布结果和重发。

AI 生成题目必须先进入草稿或待审核状态，教师审核后才可发布。主观题不能显示为已经自动批改。

### 4.8 知识库

原方案遗漏。需包含上传、来源、授权范围、解析状态、切块、向量化、版本、删除、检索测试和失败重试。删除时提示会影响的 AI 任务和历史结果；不得默认联网检索。

### 4.9 社区审核

原方案遗漏。需包含审核队列、风险标签、审核详情、原文与附件、举报记录、AI 预审依据、通过、驳回、要求修改、隐藏、恢复和操作记录。

AI 预审只是风险提示，不能直接公开或删除帖子。

### 4.10 监管机器人与系统设置

机器人列表/详情要按文本、读图、向量分组，展示供应商、模型、启用、就绪、最近测试和用途。配置项是 provider、model、endpoint、secretRef、enabled、systemPrompt、restrictionWords；不可出现真实 API Key 输入/查看。

系统设置需区分教师可见的个人设置和管理员可见的账号角色、认证、支付、备份、审计日志和系统开关。监管机器人不得放入系统设置。

审计日志要支持按时间、操作者、实体、操作类型、关键词筛选和 CSV 导出；敏感字段掩码。备份/恢复要有影响说明、强提醒和二次确认。

## 五、响应式与交互补充

### 5.1 学生端移动导航

学生端移动端可以使用底部导航，但建议只放“首页、课程、计划、工具、更多”五个高频入口。商城、自测、自测档案、社区和账户资料进入“更多”或二级页。不要把所有桌面菜单压成一排底部 Tab。

教师端移动端不建议使用完整底部 Tab。教师端以抽屉导航 + 顶部页标题 + 工作台快捷入口为主；数据表格改为字段分组卡片，批量操作使用底部操作条或全屏操作页。

### 5.2 固定区域与滚动

学生背单词和单题练习应保证常用桌面高度内无需为单次操作滚动。需要固定高度的区域包括：单词释义预留区、题目操作栏、考试交卷栏、移动端关键表单提交栏。

固定底部栏必须加足内容底部留白，并适配 iPhone 安全区；不能遮挡最后一项内容、题目选项或提交反馈。

### 5.3 动效

默认动效采用 150–220ms 的淡入、状态颜色过渡、轻量位移；不要给卡片、表格和导航配置大幅浮动或强制滑入。题目正确/错误反馈应先确保颜色、图标、文字可见，再叠加动画。

尊重 `prefers-reduced-motion`：关闭卡片切换、骨架闪烁、进度环连续动画和弹层滑动，保留即时状态切换。

### 5.4 状态库

除按钮、加载、Toast 外，设计必须补出：空数据、无搜索结果、无权限、未开通权益、服务未配置、网络错误、服务器错误、同步失败、保存失败、草稿、审核中、已发布、已下架、待开始、进行中、待提交、已提交、待批改、已完成、已逾期、已拒绝、已停用、已恢复、本地保存和接口待接入。

“无权限”“未开通”“未配置”“内容为空”不是同一种空态。每一种状态必须给出不同解释与不同可执行动作。

## 七、仅需产品方确认的事项

以下问题会影响功能范围或数据能力，不能由视觉设计自行决定。除以下事项外，其余页面与交互细节可按照本审阅文件和《网站设计文档》自行推演。

1. 学生端账号资料页：当前代码中账户入口是提示性占位，并无完整可路由资料页。确认是否将“账户与个人资料”纳入本轮实际开发范围；建议纳入，因为休息日、自测推送和目标信息需要统一入口。

2. 商城订单：当前可使用人工审核订单与全局免费开放两种模式。确认首期设计是否要同时呈现两种模式，还是只展示当前实际启用模式；建议设计同一套订单状态框架，并通过配置决定是否显示价格、提交申请和审核状态。

3. 社区互动：当前产品已有发帖与审核，评论、点赞、收藏、举报在全站设计文档中被列为目标能力，但可能没有完整后端闭环。确认本轮是只设计并标注“后续能力”，还是需要纳入首期可实现范围；建议完整设计，但在交付中标记为“需接口支持”。

4. 通知中心：当前顶部通知入口尚未接入消息服务。确认本轮是否设计真实通知中心；建议仅设计“未启用/暂无通知”占位与未来入口，不为当前版本虚构消息数据。

5. 多因素认证与忘记密码：架构允许管理账号未来启用双因素认证，但当前首期登录主体是账号密码和强制改密。确认是否本轮实现；建议设计为可扩展的安全流程，但首期只展示账户密码、强制改密和联系管理员路径。
