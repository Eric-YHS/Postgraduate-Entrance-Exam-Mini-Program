# 上岸考研学习平台：最终全站 UI/UX 设计规范

> 版本：最终整合版
>
> 定位：本规范是全站视觉、布局、交互和实现的唯一设计依据。既有产品功能、权限边界、学习规则和数据状态必须保持；《公共课设计规划》仅作为苹果式视觉语言、排版节奏和组件形态的参考，不得覆盖本规范中的业务要求。

## 1. 设计总原则

### 1.1 设计目标

将“上岸考研学习平台”设计为一套清晰、克制、灵动且可信的长期学习工作台。它不是营销首页，也不是满屏卡片的数据后台。学生应在打开页面后的数秒内知道今天做什么、学习做到哪里、下一步是什么；教师应能在高密度界面中识别风险、维护内容、安排计划和审核结果；管理员应能在不暴露敏感信息的前提下完成配置与审计。

### 1.2 优先级

功能正确性、信息层级、可执行操作、状态真实、视觉一致性、装饰效果依次降低。任何导致任务规则错误、权限误导、按钮跳动、文字重叠、单次学习需要不必要滚动的视觉方案均不可采用。

### 1.3 风格定义

采用“苹果式学习工作台”而非复制 Apple 官网。关键词为：留白克制、平面清晰、内容优先、柔和层级、少量透明材质、精确排版、细节有反馈。

视觉情绪使用一处主要撞色，而不是整页渐变。主品牌蓝负责全局关键操作与焦点；学科撞色仅用于科目识别、进度、任务色条、局部标题线和小范围强调。学生端允许更柔和的色块与动态反馈；教师端保持白底、细边框、紧凑表格和低饱和风险提示。

## 2. 不可改变的产品规则

1. 学习工具内容完成与学习计划任务完成是两套记录。完成单词、题目或代学内容不自动勾选今日计划；勾选计划也不自动增加工具学习进度。
2. 今日任务按完成进度而非日历日期推进。未完成项次日继续出现；一行内全部分项完成后才推进下一行。
3. 英语单词必须先点击“认识 · 查看释义”，再点击“已掌握并进入下一个”才记为完成；昨日复习不增加新学习总量，也不推进位置。
4. 政治/英语选择题必须提交答案并看见结果才记为完成；昨日复习不推进新学习位置。
5. 代学题必须在时间结束，或提前结束并打开答案/分析后，才记为完成。
6. 学生不得访问其他学生数据；教师和管理员的访问由后端权限控制，前端不能伪造权限。
7. AI、支付、课程权益、后台同步的成功状态必须建立在真实服务端成功结果上；未接入或未配置必须如实说明。
8. API Key、支付密钥、对象存储密钥和永久凭证不得显示、保存或记录在浏览器端。

### 3.1 色彩 Token

| `--ink` | `#1D1D1F` | 主文字 |

| `--brand` | `#0071E3` | 主操作、链接、焦点、全局进度 |
| `--brand-soft` | `#E8F2FF` | 选中背景、轻提示 |
| `--success` | `#15803D` | 已完成、通过 |
| `--success-soft` | `#EAF8EE` | 成功底色 |
| `--warning` | `#B54708` | 注意、临期、待确认 |
| `--warning-soft` | `#FFF4E5` | 警告底色 |
| `--danger` | `#D92D20` | 错误、拒绝、危险操作 |
| `--danger-soft` | `#FFF0EE` | 错误底色 |
| `--politics` | `#635BCE` | 政治识别色 |
| `--english` | `#15803D` | 英语识别色 |
| `--math` | `#C05A00` | 数学识别色 |
| `--major` | `#0F766E` | 专业课识别色 |

所有状态必须同时使用颜色、图标与文案，不能依赖颜色传达唯一含义。不得使用整屏紫色渐变、彩色光晕、渐变球或大面积高饱和色块。

### 3.2 字体与数字

字体采用 `-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif`。数字、时间、分数、倒计时使用支持等宽数字的字体特性 `font-variant-numeric: tabular-nums`。

桌面字号：10px 极小辅助、12px 标签/说明、13px 表格辅助、14px 正文、15px 表单与重点正文、16px 题干与内容强调、17px 卡片标题、20px 模块标题、24px 普通页面标题、32px 首页大标题、36px 关键数字。移动端页面标题不超过 24px。

### 3.3 空间、尺寸和层级

使用 4px 基准网格。常用空间为 4、8、12、16、20、24、32、40、48、56、64px。按钮和控件高度可使用 32、36、40、44、48、52、56px。不要为了遵守网格而牺牲触控区、安全区或文字可读性。

桌面内容区最大宽度为 1440px；正常页面左右内边距 32–48px；移动端为 16px。学生端桌面侧栏 240px，折叠为 72px；教师端侧栏 224px，折叠为 72px；顶部栏 56px。

页面主区块优先使用留白、浅底和一条细边框建立层级。重复列表项、工具卡片、弹窗和明确独立的工作面板可以有 8px 或 12px 圆角；不要产生“卡片里套卡片里再套卡片”的结构。

### 3.4 材质、圆角和阴影

圆角：大面板与弹窗 12px，按钮/输入框/小面板 8px，标签 999px 或 4px（按内容性质选用）。静止阴影 `0 2px 8px rgba(16, 24, 40, .04)`，悬停阴影 `0 8px 20px rgba(16, 24, 40, .08)`，模态阴影 `0 20px 60px rgba(16, 24, 40, .16)`。

仅顶部栏、账户菜单、轻量 Popover、移动端底部栏允许使用半透明白色加背景模糊；题库表格、长列表、编辑表单、学习主体和管理页主体必须使用不透明表面。低性能或减少透明效果时回退到实色。

### 3.5 按钮、输入和反馈

主按钮使用品牌蓝白字；次按钮为白底细边框；安静操作使用文字/图标按钮；危险操作为红色文字或红色实体按钮，必须二次确认。按钮不得仅用不熟悉图标表达重要动作。

默认、hover、focus、pressed、disabled、loading、success、error 状态均需统一。焦点使用 2px 品牌色边框和 4px 低透明外圈。加载时保留按钮宽度，显示小型转圈和动作文字，禁止页面布局变化。

Toast 位于顶部栏下方，且只在真实操作结果返回后显示。表单错误优先就地展示；网络/服务异常使用可重试的状态条或面板，不能只给短暂 toast。

## 4. 全站布局与导航

### 4.1 学生端

桌面端为“轻侧栏 + 固定顶栏 + 主内容区”。侧栏包含：学习首页、我的课程、商城、练习与自测、自测档案、学习计划、学习工具、学习社区。账户资料通过顶部头像菜单进入，不重复放入侧栏。

学生侧栏顶部显示品牌标识和“上岸·考研学习平台”；激活项使用低饱和品牌蓝背景、蓝色图标/文字与 3px 左侧色条。导航不使用大面积渐变。顶栏左侧显示面包屑，右侧显示通知入口、账户菜单、退出。通知服务未接入时明确显示未启用，不伪造未读数。

移动端底部仅保留：首页、课程、计划、工具、更多。商城、自测、档案、社区、账户资料收纳在更多菜单中。学习中的题目、单词和考试使用独立沉浸式页面，保留顶部返回和必要状态，不显示全局底部导航。

### 4.2 教师与管理员端

教师端侧栏包含：数据看板、学员管理、课程与商品、复习规划、知识库、应用管理、带背后台、自测、社区审核、监管机器人、系统设置。教师端使用紧凑但不拥挤的工作台布局，侧栏与主内容区使用清晰分区；表格、筛选器、批量操作和详情页优先保证扫描效率。

平台管理员沿用教师端框架，但按权限显示账号角色、认证、支付、审计、备份等系统能力。监管机器人始终为独立一级入口，不能放进系统设置。

教师端移动端使用抽屉导航、页面标题和分组卡片，不使用塞满全部菜单的底部 Tab。数据表格在移动端转为字段分组卡片，批量操作进入全屏/底部操作条。

## 5. 学生端页面规范

### 5.1 学习首页

首屏结构为“欢迎与倒计时带 + 今日执行面板 + 辅助状态栏”。欢迎区左侧展示问候、当前学习阶段和考研日期；倒计时作为视觉锚点，使用等宽数字，避免过度动画。右侧展示今日计划任务完成率，必须清楚标为“今日计划完成”，不与课程或工具进度混合。

今日执行面板为页面核心，按科目分组。每项显示科目色条、任务名称、任务分项完成情况、预计时长、顺延/新任务标记和可执行动作。分项任务显示“已完成 4/5”，点击完成时可填写实际完成情况；取消完成必须说明影响。任务可跳转到对应课程、工具、自测或计划详情。

右侧/下方辅助区包括：今日自测入口、目标分、学习回顾、休息日状态、未来 7 天入口。日/周/月自测卡清楚显示科目、类型、状态与开始动作。没有今日任务时，分别设计计划未分配、前置未完成、休息日、加载失败四种状态。

休息日状态替换任务主区为“休息愉快，好好休息”，仍可查看历史、调整休息日。当天设置休息日不改变当日已生成推送；设置页需清楚说明提前一天生效。

### 5.2 我的课程与课程详情

课程列表按公开课、政治、英语、数学、专业课分类，支持二级分类与搜索。已报名和公开课程正常展示；未开通课程显示摘要、权益状态和“申请开通/查看商城”，不显示可播放假象。

课程卡使用 16:9 封面、科目标签、标题、最近学习位置、课程进度和“继续学习”。卡片高度由内容控制，但标题最多两行，进度与主操作位置稳定。

课程详情采用“课程概要 + 章节目录 + 内容工作区”。章节目录显示完成、进行中、未开始、锁定；内容区处理视频加载、播放失败、无权限、课程下架、资料阅读和继续学习。播放地址不得向用户展示。课程下架时保留已学习历史但显示访问限制与联系路径。

### 5.3 商城、购买申请和订单

商城按商品列表、商品详情、申请确认、订单列表、订单详情组织。商品显示适用科目、内容清单、价格/当前开通方式、权益有效期和状态。

订单状态统一为：待提交、待审核、待补充、已通过、已拒绝、已取消、开通中、已开通、开通失败。人工审核期间只显示“等待审核”，不得提前展示课程已开通。权益开通成功后提供“进入课程”。若全局免费开放，显示“当前开放学习”，而不是伪装成支付成功。

### 5.4 练习与自测

自测入口按当日可用测试展示类型、科目、题量、预计时长、截止时间和状态；月测优先于周测，周测优先于日测。不同科目题型由配置决定，UI 不写死为选择题。

答题页分为顶部状态区、题号导航、题目工作区和固定提交栏。顶部显示试卷名称、剩余时间、已答数量；底部固定栏显示未答数量与交卷操作。移动端题号导航折叠。提交前给出未答题提醒，提交失败保留答案并可重试。

结果页显示分数、用时、答题总览、错题、解析、知识点分布、教师批注和 AI 辅助建议。AI 建议标出生成/审核状态。主观题显示待批改，不能表现为已自动评分。

### 5.5 自测档案

档案列表整合入学摸底、日测、周测、月测，支持按时间、科目、类型筛选。记录显示分数、总分、完成时间、错题数、批改状态和教师反馈状态。

详情按“作答概览、答题与解析、错题、教师反馈、AI 建议”组织。空态必须区分未参加和无权限；历史答题快照不能因题库后续更新而失去可读性。

### 5.6 学习计划

计划页设为今日、未来 7 天、全部计划三个视图。今日强调当前活跃任务行；未来 7 天从当前未完成行向后展开，不伪造固定日历任务。顺延任务需使用明确标签与说明。

计划详情展示来源、教师、科目、阶段、开始时间、任务行、分项任务、预计时间、完成历史和调整记录。学生只能完成、查看和申请调整，不能编辑被锁定的任务结构。

### 5.7 学习工具总览

工具页采用功能分组而非单纯图标墙。每张工具卡显示用途、适用科目、当前内容完成、剩余、昨日复习数量、最近使用时间、访问状态和明确下一步。

状态区分已开通、未开通权益、服务未配置、内容为空、正在学习、已完成、继续学习。不同状态提供不同动作：未开通去商城/联系老师，未配置仅查看状态，内容为空返回工具页或稍后查看。

### 5.8 英语背单词

先进入词书选择页：词书封面/名称、总词数、已学习、剩余、昨日完成、继续学习、复习昨日。正常学习从第一个未完成位置继续；昨日复习只取昨日完成词。

单词学习页在常用桌面高度内完成一次操作。结构为：顶部轻量状态栏、中央单词主体、固定释义预留区、右侧竖排决策区。中央显示单词、音标和一次发音按钮；未查看释义时，中文意思与记忆助剂完全不可见。

释义预留区必须始终占位，点击“认识 · 查看释义”后原位显示中文释义、例句/记忆助剂，不得向下推移操作按钮。右侧操作区固定三个统一尺寸按钮：认识·查看释义、已掌握并进入下一个、暂不掌握，下一词。未查看释义前，“已掌握”禁用；昨日复习模式下不提供推进新学习位置的完成动作。

避免朗读次数、间隔、重新开始、暂停、重置等干扰正常学习的控制。发音失败、释义缺失、词书为空、昨日无可复习内容、学习完成、接口待接入均需有明确状态。

### 5.9 政治选择题与英语选择题

先选择题库，显示总题数、完成、剩余、昨日可复习、继续学习/复习昨日。答题页显示题号、题干、选项、进度与提交按钮；提交前不显示答案和解析。

提交后锁定本题选择，显示正确/错误状态、正确答案、解析、知识点与下一题。正确与错误不能只用颜色，需要图标与文字。正常模式下提交且可见结果时才记完成；复习模式不写入新学习进度。

### 5.10 代学/限时学习

代学入口显示可用题库、计时规则、完成、剩余、昨日复习。学习页突出但不干扰的倒计时、题目、答题区域、提前结束与答案/分析区域。

提前结束须二次确认并告知剩余时间；只有时间结束或提前结束后打开答案/分析才记完成。设计断网、恢复会话、服务端计时失败、会话失效、昨日无复习内容等状态。

### 5.11 难题逐步讲解

页面流程为：选科目、上传图片、补充说明、确认提交、识别中、生成中、结果。上传区支持拖放/选择、预览、删除、重传、格式与大小提示。

结果固定分为审题、考点与方法、分步推导/作答、最终答案、易错点与复查。AI 未配置时阻止提交并明确说明；识别或生成失败保留输入并允许重试。演示/草案结果必须标记，不能伪装为真实 AI 服务结果。

### 5.12 学习社区与账户资料

社区包括帖子流、搜索、标签筛选、发帖、附件、帖子详情、评论/互动能力、举报和我的发布。帖子状态区分审核中、已公开、需修改、已驳回、已隐藏；仅向作者展示明确原因，不公开内部风险评分。

账户资料从头像菜单进入，包括个人信息、手机号、密码修改、考研目标、报名科目、目标分、当前阶段、休息日、自测推送偏好和收货信息。敏感字段掩码展示，保存反馈真实反映同步状态。

## 6. 教师与管理员页面规范

### 6.1 数据看板

使用“指标带 + 待办队列 + 风险学员 + 近期动态”四层布局。指标展示学员活跃、计划完成率、自测提交、订单状态等，每个指标写清统计区间、更新时间和数据源。读取失败显示“暂无法读取”与重试，不显示 0。

待办队列包括登记、订单、社区审核、AI 待确认结果。风险学员表显示风险理由，进入学生详情或调整建议时保留筛选上下文。

### 6.2 学员管理与学员详情

学员管理提供搜索、科目/状态/阶段筛选、排序、分页、批量操作、新增、登记导入、停用/恢复、重置密码。危险操作须描述影响并保留历史数据。

详情使用“身份概要 + 标签页”而非单一长页。标签包括：基础档案、学习概览、学习计划、自测、错题与薄弱点、课程权限、AI 建议、操作记录。概览区显示姓名、状态、学员类型、科目、目标、最近活跃、风险与快捷操作。

未来 30 天 AI 检测显示在任务列表末尾作为建议区，教师可采纳、修改、忽略并留下人工处理记录。AI 不得直接覆盖完整计划。

### 6.3 课程与商品

该模块负责课程、章节、媒体、商品、订单审核和课程权益。课程编辑包括标题、封面、简介、科目、分类、标签、价格、章节、视频、资料和发布检查。媒体显示上传、转码、可播放、失败、删除等状态。

商品管理包括商品清单、商品详情、包含内容、价格、封面、上下架和订单入口。发布/下架时说明学生可见性、已学习记录与既有权益影响。

### 6.4 复习规划

此模块负责计划模板、版本、学生计划副本与一对一调整。模板列表显示名称、科目、阶段、版本、状态、使用人数、更新时间。编辑页面包含任务行、分项、预计时长、前置关系、可见性和版本说明。

“编辑模板新版本”与“调整某学生计划”必须是独立路径。模板更新不回写已分发学生计划；一对一调整需要预览影响范围与保存历史。

### 6.5 应用管理与带背后台

应用管理维护英语词书、政治选择题、英语选择题、工具说明、排序、可见范围和启用状态。词书编辑维护单词、音标、释义、发音、例句/助记；题库编辑维护题干、选项、答案、解析、标签、难度、知识点和状态。它不管理学生个人完成记录。

带背后台仅负责代学/限时学习题库、计时规则、题目顺序、可用科目、启用状态与会话边界。内容修改需提示对进行中会话、昨日复习和历史记录的影响；下架不静默删除历史。

### 6.6 自测、题库与试卷

教师端自测包括题库、题目编辑、AI 草稿审核、组卷、发布预览、分发、作答状态、客观题评分、主观题批改与结果发布。题目状态包含草稿、待审核、已发布、已下架、版本冲突；AI 题目必须经教师审核后才发布。

试卷分发页显示学生、开始期限、作答时长、分发链接与状态（已分发、已开始、已提交、已过期）。主观题在教师确认前始终为待批改。

### 6.7 知识库、社区审核、监管机器人、系统设置

知识库管理上传、来源、授权范围、解析、切块、向量化、版本、检索测试和删除。显示全过程状态并支持失败重试；删除说明影响，不默认联网检索。

社区审核包括审核队列、原文/附件、举报、AI 风险提示、审核历史及通过/驳回/要求修改/隐藏/恢复。AI 仅辅助判断，最终结果由人员确认。

监管机器人按文本、读图、向量分组。机器人详情管理 provider、model、endpoint、secretRef、enabled、systemPrompt、restrictionWords、就绪状态、最近测试与影响范围。只显示密钥引用名和服务端状态，绝不设计 API Key 输入、查看或复制。

系统设置包括账户角色、认证、支付、审计、备份和系统开关。审计支持筛选和 CSV 导出，敏感值掩码；恢复备份需强提醒、影响说明与二次确认。

## 7. 统一状态、权限和跨页面规则

所有页面至少设计：加载、内容成功、空数据、无搜索结果、无权限、未开通权益、服务未配置、保存中、保存成功、保存失败、网络错误、服务端错误、同步失败、草稿、审核中、待开始、进行中、待提交、已提交、待批改、已完成、已逾期、已拒绝、已停用、恢复确认、删除确认。

无权限表示账号不允许访问；未开通表示可通过权益/申请获得；未配置表示业务服务不可用；内容为空表示当前没有可用内容。这四种状态必须使用不同图标、文字与下一步动作。

从学生首页任务进入课程、工具、题目或自测后，返回应刷新关联状态且保留计划上下文。从工具总览进入词书/题库后，返回保留筛选和滚动位置；从词书学习页返回，回到该词书详情。教师从看板进入列表、从列表进入详情后，返回保留筛选、页码和选择状态。

所有关键时间同时展示明确含义与绝对时间；相对时间仅作辅助。课程进度、工具内容完成、计划任务完成必须分别命名和分别展示。

## 8. 响应式、动效与无障碍

桌面验收宽度为 1440、1280、1024；移动验收宽度为 390、375。学生背词、单题练习和考试在典型桌面高度内完成一次核心操作，不要求每题/每词滚动。教师表格允许横向滚动，但身份、状态和操作列优先固定；小屏转字段分组卡片。

动效时长为 150–220ms，以淡入、轻微位移、颜色渐变为主。题目正确/错误、单词切换、弹层出现均不得造成布局大幅位移。支持 `prefers-reduced-motion`，关闭非必要位移动效与闪烁。

所有表单有可见 label；图标按钮有 aria-label 与 tooltip；键盘可完成主要流程；焦点清晰；状态不只使用颜色；固定底栏必须避开手机安全区并为内容预留底部空间。

## 9. 实施验收清单

1. 所有页面都基于既有业务功能与权限边界，不因视觉改版删改学习规则。
2. 任何“已保存、已生成、已开通、已提交”均对应真实成功结果。
3. 学生端、教师端与管理员端导航各自清楚，不存在功能重复入口。
4. 每页有空、错、加载、权限、未配置和成功状态，不把不同状态混成一个空白页。
5. 单词释义显示不移动决策按钮；桌面端单词学习不需要每词滚动。
6. 题目在提交前不暴露正确答案；代学在符合规则前不记录完成。
7. 教师表格可扫描、可筛选、可返回上下文；移动端没有文字挤压或被固定栏遮挡。
8. 不存在前端 API Key、伪造 AI 结果、伪造同步成功、隐藏权限绕过或静默删除历史的设计。
9. 设计 token、组件状态、桌面/移动断点与关键交互均可被 React/CSS 工程师直接实现。

## 10. 尺寸、方框与版式执行规格

本节为 React/CSS 实现的硬性尺寸规则。除内容自然高度、文本换行和无障碍触控区域外，不允许用随意的像素值替代以下体系；同一类别的组件必须复用相同规格，避免出现按钮忽大忽小、列表行高不齐或卡片边界混乱的问题。

### 10.1 页面框架尺寸

| 区域 | 桌面规格 | 平板规格 | 移动规格 |
| --- | --- | --- | --- |
| 顶部栏 | 固定 56px 高 | 固定 56px 高 | 固定 56px 高 |
| 学生侧栏 | 240px 展开 / 72px 折叠 | 72px 折叠优先 | 不展示 |
| 教师侧栏 | 224px 展开 / 72px 折叠 | 72px 折叠优先 | 抽屉，宽 304px |
| 页面最大内容宽 | 1440px | 不超过可视区 | 100% |
| 主内容内边距 | 32px；1440px 宽度可增至 48px | 24px | 16px |
| 页面区块间距 | 24px 或 32px | 20px 或 24px | 16px 或 20px |
| 模块标题与内容间距 | 16px | 16px | 12px |
| 移动底部导航 | 不适用 | 不适用 | 内容高度 56px，连同安全区最多 84px |

页面结构固定为“顶部栏、页面标题区、主工作区”三层。不要在每个页面额外嵌套一层无意义的外卡片；教师表格页可直接以白色工作面板承载筛选、表格与分页，学生页面可用一个主面板加少量辅助面板表达优先级。

### 10.2 栅格、卡片与容器

学生首页桌面使用 12 列栅格，列间距 24px；主执行区占 8 列，辅助区占 4 列。宽度低于 1180px 时改为主区 7 列、辅助区 5 列；低于 1024px 时改为单列，今日执行区始终排在辅助区前。

课程、商品、工具卡列表使用自适应栅格：大屏每行 3 张，中等桌面每行 2 张，移动端单列。卡片最小宽度 280px；课程封面固定 16:9；工具卡建议最小高度 196px；卡片内容区内边距 16px，复杂卡片可使用 20px 或 24px。卡片标题最多两行，所有底部进度与主操作应通过 `margin-top:auto` 保持同一水平线。

通用面板最小高度不应作为装饰性限制；只有必须稳定的学习页、指标卡、列表行、操作栏和媒体框可定义固定或最小高度。指标卡高度 132px 至 148px；学生首页倒计时带最小高度 152px；教师待办项最小高度 64px；普通列表项最小高度 56px；带双行辅助信息的列表项最小高度 72px。

### 10.3 按钮、输入框、标签与选择控件

| 组件 | 规格 | 使用规则 |
| --- | --- | --- |
| 紧凑按钮 | 32px 高 | 表格行内、筛选辅助操作；不用于关键提交 |
| 常规按钮/输入 | 36px 或 40px 高 | 筛选、表单、列表主操作 |
| 主要表单操作 | 44px 高 | 登录、保存、提交、确认等明确流程终点 |
| 学习沉浸页主操作 | 48px 至 56px 高 | 单词、题目、交卷、开始学习 |
| 图标按钮 | 32px 或 36px 正方形 | 必须有 aria-label 与 tooltip |
| 输入框 | 40px 或 44px 高 | 文本输入、选择、日期、搜索 |
| 多行输入 | 最小 96px 高 | 保持可拉伸，禁止将长文本挤入单行 |
| 标签 | 20px 或 24px 高 | 仅用于状态、科目、轻量分类，不替代按钮 |
| 复选/单选控件 | 可视 18–20px，触控区域至少 36px | 状态变化不能只依靠颜色 |

按钮圆角统一 8px，标签圆角可使用 4px 或胶囊形。主要按钮最小水平内边距 16px，常规按钮 12px，文字与图标间距 6px 或 8px。一个动作在同一页面中只能有一种尺寸和一种优先级：例如“保存”不能在筛选栏为 32px、表单中又为 52px，除非两者所在流程等级明确不同。

按钮文字使用动词和结果对象，例如“保存计划”“提交答案”“进入课程”。加载状态锁定现有尺寸，图标转圈占用固定空间，不能将“保存”突然替换成更长文本而撑开布局。

### 10.4 表格、筛选与管理界面

教师端表格表头高度 40px，默认数据行高度 56px，含双行信息的数据行高度 64px 或 72px。表格单元格横向内边距 16px，纵向内边距 12px；表头文字为 12px、600 字重，数据正文 14px，辅助时间和来源信息 12px 或 13px。

筛选栏采用单层流式排列，最小高度 56px，内部控件间距 8px 至 12px。搜索框桌面默认宽 240px 至 320px；日期范围、下拉筛选宽 144px 至 200px。筛选项过多时折叠为“更多筛选”抽屉，不允许挤压为无法点击的小控件。

批量操作条固定在列表上方或底部，桌面高度 48px，移动端使用底部安全区操作条，最小高度 56px。出现时只影响对应列表区，不得覆盖表格数据或遮挡分页。

### 10.5 表单、抽屉、弹窗与空状态

表单字段垂直间距为 16px；标签与控件间距 6px；错误说明距控件 6px，使用 12px。双列表单只在内容区宽度不低于 760px 时使用，窄屏全部变为单列。字段说明应出现在输入前或紧邻输入后，不可借由 placeholder 承担唯一说明。

确认弹窗宽度按影响范围分级：普通确认 420px 至 480px，复杂表单 560px 至 720px，危险批量操作最大 640px。弹窗内边距 24px，标题区与正文间距 12px，底部操作区与正文间距 24px；移动端改用底部抽屉或全屏流程。

右侧详情抽屉宽度为 480px 至 560px；复杂编辑抽屉 640px 至 720px。空状态面板最小高度 240px，图标 32px 至 40px，标题 17px，说明 14px，并提供一个与状态对应的下一步动作。

### 10.6 学习沉浸页的稳定几何

背单词、选择题、代学和考试页优先使用专用沉浸式布局，不能复用普通卡片列表的纵向堆叠结构。

背单词桌面主体最大宽度 1120px，采用“主学习区 + 210px 决策列”。顶部状态区高度 48px 至 56px；单词主体区最小高度 216px；释义与记忆助剂区域固定预留 124px 至 152px。三枚决策按钮纵向排列，尺寸完全一致，每枚最小高度 72px，间距 10px 至 12px。释义出现、隐藏、加载失败或缺失时均只能替换预留区内容，绝不能推动按钮、进度或单词主体位置。

选择题与代学页桌面主工作区最大宽度 960px 至 1120px。题干区内边距 24px 至 32px，选项最小高度 48px，选项间距 12px；提交/下一题操作区保留固定高度 72px。考试页底部交卷栏桌面高度 72px，移动端至少 64px 加安全区，正文底部需要留出该高度与 16px 的额外安全空间。

计时器、题号、学习进度和关键操作均使用等宽数字或固定宽度容器，倒计时数值变化不引起横向跳动。学习结果出现后在既有题目区内展开，不得插入顶部并迫使题目整体下移。

## 11. 字体、排版与内容密度

### 11.1 字重、行高与文字长度

| 文本类型 | 字号 / 字重 | 行高 | 规则 |
| --- | --- | --- | --- |
| 首页主标题 | 32px / 600 | 1.22 | 一行优先，不作为营销标语堆叠 |
| 页面标题 | 24px / 600 | 1.3 | 与面包屑、操作区保持稳定关系 |
| 模块标题 | 20px / 600 | 1.35 | 面板内最高层级 |
| 卡片标题 | 17px / 600 | 1.4 | 最多两行截断 |
| 重点正文/题干 | 16px / 400–500 | 1.6 | 长题干可自然换行 |
| 正文/表格正文 | 14px / 400 | 1.55 | 平台默认阅读层级 |
| 表单/按钮文字 | 14px 或 15px / 500 | 1.4 | 不使用过小文字承载关键操作 |
| 标签/辅助 | 12px 或 13px / 400–500 | 1.45 | 用于时间、来源、解释 |
| 极小提示 | 10px / 400 | 1.4 | 仅用于非关键技术辅助信息 |
| 关键数字 | 32px 或 36px / 650 | 1.05 | 使用等宽数字，不与正文混排 |

正文段落建议单行长度控制在 24 至 34 个中文字符的视觉范围；说明文字在桌面端最大宽度 680px，避免横跨整页。教师端长字段需使用省略、展开或详情入口；禁止为显示完整文本无限增加表格列宽。

### 11.2 排版原则

标题、说明、数据和操作要有明确的四层秩序。一个面板内最多突出一个主标题、一组主数字或一个主操作，不能同时使用超大标题、彩色大数字、多个实体按钮和大片背景色争夺注意力。

学生端在学习状态中使用更充足的垂直留白；教师端在列表和编辑状态中通过对齐、分隔线和字号层级提高扫描效率，不靠缩小文字制造“高密度”。移动端正文不低于 14px，核心题干与关键反馈不低于 16px。

## 12. 交互动画与状态转场

### 12.1 动效原则

动画只承担三个任务：解释状态变化、维持空间连续性、确认用户操作。不得使用为了“炫酷”而存在的持续漂浮、弹跳、强光晕、自动轮播或大面积渐变流动。

标准过渡时间为 180ms；快速微反馈 120–150ms；弹窗、抽屉与页面内重要状态切换 200–240ms。缓动使用 `cubic-bezier(.2, .8, .2, 1)`；按下反馈使用 100–120ms 的颜色与轻微缩放，缩放不小于 `0.98`。

### 12.2 组件动效规范

| 场景 | 动效 | 禁止事项 |
| --- | --- | --- |
| 按钮 hover | 背景、边框或阴影在 150ms 内过渡 | 不做明显上浮或大幅缩放 |
| 按钮 pressed | `scale(.98)` 与颜色压暗 | 不改变按钮宽高 |
| 输入 focus | 边框与外圈淡入 150ms | 不推动相邻字段 |
| Toast | 顶部轻微淡入下移 180ms | 不以 toast 替代表单错误 |
| Popover | 透明度 + 4px 位移 180ms | 不遮挡其触发控件的关键内容 |
| Modal/Drawer | 遮罩淡入 + 12px 位移 220ms | 不使用夸张弹簧、全屏旋转 |
| 列表刷新 | 行内容淡入或骨架替换 | 不让列表整体闪烁或跳页 |
| 任务完成 | 勾选、状态色与进度宽度过渡 180ms | 不自动滚动或隐藏其他任务 |
| 题目提交结果 | 在题目工作区原位展开 200ms | 不将题目或按钮向下推离可视区 |
| 单词释义 | 预留区内容淡入 160ms | 不改变预留区高度或移动决策按钮 |
| 单词/下一题切换 | 主体内容淡出再淡入，位移不超过 8px | 不采用整卡上滑、从屏外飞入 |
| 进度条 | 宽度平滑过渡 200ms | 不对每次重渲染重复播放 |
| 正误反馈 | 图标、文字和底色同步出现 | 不只闪红/绿颜色 |

### 12.3 页面与数据状态

路由切换不使用全屏滑入动画。页面标题、面包屑和主体内容可采用 160ms 的透明度过渡，但不能使导航或固定栏短暂消失。需要加载远程数据时优先显示结构对应的骨架：标题骨架、筛选骨架、列表行骨架、表格行骨架或学习主体骨架；骨架颜色保持低对比且无强烈闪烁。

异步保存时，按钮在原位显示 loading；保存成功后再显示真实结果 Toast 或行内状态。网络失败、服务端失败和同步失败必须保留用户输入与可重试路径。禁止在请求开始时预先播放成功动画，也禁止把乐观更新作为唯一可见状态。

### 12.4 减少动态效果与性能回退

必须实现 `prefers-reduced-motion: reduce`：关闭页面位移、单词/题目切换位移、骨架闪烁、进度连续补间和非必要 hover 动画；保留即时的颜色、图标和文字状态变化。对不支持背景模糊或性能不足的设备，顶部栏、Popover 与移动底栏回退为不透明白色，不影响信息可读性。

## 13. React/CSS 落地约束

样式应以设计 token 驱动，例如颜色、间距、控件高度、圆角、阴影、层级与动画时长均定义为 CSS 自定义属性；组件内部不应散落互不一致的硬编码值。建议至少定义 `--space-*`、`--control-*`、`--radius-*`、`--shadow-*`、`--motion-*` 与全套色彩 token。

页面组件负责业务内容和状态分支，通用组件负责尺寸与交互一致性。至少复用 `AppShell`、`PageHeader`、`SectionHeader`、`Panel`、`Button`、`IconButton`、`StatusBadge`、`EmptyState`、`ErrorState`、`DataTable`、`FilterBar`、`ConfirmDialog`、`Toast`、`ProgressBar`、`LearningHeader` 与 `FixedActionBar`。任何临时页面不得自行重新发明按钮、标签、卡片、错误提示或加载效果。

桌面断点建议为：1440px 及以上使用完整内容区；1024–1439px 允许侧栏折叠与卡片列数减少；768–1023px 使用紧凑布局；767px 以下进入移动模式。断点的目的在于重排，不是同比缩小桌面页面。每次改版须在 1440、1280、1024、390、375 宽度及常见笔记本高度下检查文本换行、固定栏遮挡、点击区域、弹窗可达性和学习单屏操作。

## 14. 新增验收项：尺寸、字体与动效

1. 同类型按钮、输入框、标签、表格行和卡片在全站使用统一高度、圆角、内边距和字级，不存在任意大小混用。
2. 页面在 1440、1280、1024、390、375 宽度下均不存在文本重叠、横向溢出、操作被遮挡或小于可点击区域的控件。
3. 学生端单词、选择题、代学和考试的核心单次操作不依赖滚动；内容展开不得导致关键按钮位移。
4. 所有弹窗、抽屉、固定底栏和移动导航避开安全区，并为正文预留足够底部空间。
5. 字号、字重、行高与数字对齐符合规范；关键时间、分数、倒计时采用等宽数字，表格可扫描。
6. 每一种动效均有业务意义，并符合指定时长、位移范围和减少动态效果设置；无持续炫技动画与布局抖动。
7. 加载、保存、成功、失败和重试反馈都在真实状态基础上发生，动画不伪造成功。
8. 管理端数据面板、表格与表单保持不透明、稳定和高可读性；半透明模糊只用于允许的轻量层。
