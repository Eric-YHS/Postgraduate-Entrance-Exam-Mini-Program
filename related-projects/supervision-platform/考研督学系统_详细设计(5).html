考研督学系统 · 详细设计方案

产品设计思路 · 交互逻辑 · 技术建议 · 数据流转

一、整体设计理念

这个系统的核心逻辑是 "三层漏斗 + 三端协同 + AI驱动"：

三层漏斗：免费学员 → 7天体验 → 付费学员，每一层都有明确的价值输出和转化节点
三端协同：小程序（学生学习） + 后台（老师管理） + 企业微信（机器人服务），数据统一互通
AI驱动：大模型贯穿所有机器人，预设知识库 + AI搜索双保险，减少人工成本

从商业角度看，这套体系实现了完整的闭环：免费引流 → 体验转化 → 付费服务 → 口碑裂变。

二、小程序端核心模块详解

2.1 直播授课

设计思路：小程序内直播是主方案，使用微信的 live-pusher（推流）和 live-player（拉流）组件。视频号作为辅助方案，适合公开引流课。

老师端流程：创建直播 → 设置标题/时间/科目 → 开播 → 共享课件/白板 → 互动（连麦/聊天） → 结束 → 自动生成回放
学生端流程：收到开播提醒 → 进入直播间 → 观看/听讲 → 聊天互动/提问 → 结束后可看回放

2.2 录播课程

设计思路：双重来源设计。直播结束后系统自动切片生成回放，同时老师也可以在后台手动上传录播视频（MP4格式）。课程采用章节制，每章可独立上传视频和讲义文档。

试看机制：支持设置前N节免费试看（免费学员可见），后续章节仅付费学员可见。这是转化的重要手段。

2.3 课程分类

课程分为两大维度：

分类说明管理方式
公共课政治、英语（一/二）、数学（一/二/三）统一管理，所有学生可见
专业课按专业方向划分（如计算机、金融、法律等）后台可增删专业方向目录，学生按方向查看

2.4 题库系统 — 三种刷题模式

核心交互逻辑：每科采用最适合的刷题形式：

政治刷题（选择题）：

显示题目 + A/B/C/D选项 → 学生选择答案 → 出示正确答案 + 详细讲解 → 自动记录对错
讲解内容来自老师预设的知识库或后台维护的真题解析

英语背单词：

显示英文单词 + 音标 → 显示4个中文意思选项（1正确+3干扰） → 学生选择 → 出示正确答案 → 加入生词本/已掌握词库

数学公式匹配：

显示公式左边（如 sin²x + cos²x） → 显示4个右边选项 → 学生选择匹配 → 出示正确答案

数据价值：每次刷题都会记录学生的对错，这些数据会同步给全程规划老师和错题本，形成学习画像。

2.5 错题本

自动收集学生在刷题和自测中做错的题目，按科目分类展示。学生可以：按科目筛选查看、反复练习错题、标记"已掌握"移出错题本。

设计价值：错题本是学生端的核心学习工具，也是全程规划老师判断"哪些还不会"的重要数据来源。

2.6 论坛社区 + AI审核

学生可以在论坛发帖求助（如"这道高数题怎么解"），老师可以发帖答疑或发布重要通知。所有帖子在发布前经过AI自动审核，检测敏感词和违规内容，通过后自动发布。

三、后台管理系统核心模块详解

3.1 数据看板

登录后台首先看到的就是数据看板，集中展示核心指标：

  • 学员数据：总学员数、免费/付费占比、新增注册趋势（日/周/月）
  • 活跃度：日活（DAU）、周活、月活、平均学习时长
  • 课程数据：课程总数、总播放量、完课率
  • 营收数据：付费学员数、收入趋势、单科vs全科购买比例
  • 机器人数据：总对话量、响应率、未解决问题数（需人工介入）

3.2 内容管理 — 同步机制

关键设计：后台发什么，小程序就显示什么。
后台新增课程 → 保存到数据库（标记状态"已发布"） → 小程序端拉取数据时自动获取 → 显示在课程列表
后台修改/下架课程 → 更新数据库状态 → 小程序端同步更新/隐藏

这种设计的好处是：老师不需要任何技术操作，在后台点一下发布，学生端就立刻能看到。

3.3 学员管理 — 一对一复习计划

这是整个系统最具价值的核心功能之一。每个付费学员都可以单独上传复习计划：

学员列表 → 点击某个学员 → 进入详情页 → 查看基本信息（姓名/电话/毕业院校/目标院校/当前进度） → 上传/编辑该学员的复习计划

复习计划支持按时间分段设置（如8:00-9:00背单词、10:00-12:00高数），这些时段会同步给督学机器人，实现到点自动提醒。

3.4 知识库/语料库 — AI的大脑

这是所有机器人智能回复的知识底座。老师在这里上传和管理的资料，会被AI用来回答学生问题。

工作原理（RAG 检索增强生成）：
学生提问 → AI先在知识库中搜索最匹配的内容 → 如果找到 → 用预设内容回答（准确可控）
如果没找到 → AI使用大模型自身能力 + 联网搜索 → 生成回答
优势：常见问题用预设答案（精准），新问题用AI搜索（全面），两者互补

可以上传的内容：考研政策文件、院校分数线汇总、常见问题FAQ、真题解析、课程讲义等。支持PDF、Word、TXT等格式。

3.5 消息模板管理

督学机器人每天发什么消息、什么格式，由这里定义：

时间点模板示例说明
8:00 计划推送「早安{姓名}！今日学习计划：\n{时段1}：{科目}\n{时段2}：{科目}\n...」插入变量，自动填入学生信息
到点提醒「{姓名}同学，{时间}了，该学{科目}啦！点击查看详情」根据学生个人计划自动触发
22:00 检查「{姓名}同学，今天的任务完成了吗？\n✅ {时段1}：{状态}\n❌ {时段2}：{状态}\n请回复完成情况～」学生回复后自动存档

3.6 机器人管理

管理所有机器人的地方，包含：

  • 免费答疑机器人：配置可回答的问题范围、预设答案
  • 付费机器人管理：哪些机器人入群（可选督学/解答/择校/自测/规划），新建/移除机器人
  • 对话记录：查看所有学生与机器人的对话历史，支持按学生/时间/机器人筛选
  • 预留扩展：这里保留了"新建机器人"入口，后续可以按需添加（如政治答疑机器人、专业课机器人等）

四、企业微信机器人体系详解

4.1 自动拉群完整流程

1 学生付费报名成功
↓
2 系统通过企业微信API自动创建群聊「{学生姓名}·考研专属服务群」
↓
3 自动邀请：学生本人 + 指定老师（1-多位） + 指定机器人入群
↓
4 机器人自动发送欢迎消息，并开始采集学员信息
↓
5 AI提取关键信息 → 自动归档到后台学员档案

4.2 督学机器人 — 一天的时间线

时间触发条件行为说明
08:00定时任务推送当日分段学习计划内容来自后台设置的该学员个人计划
各时段到点计时器匹配计划时段私信提醒「该学XX科目了」如计划中10:00-12:00是高数，10:00发提醒
22:00定时任务私信检查各时段完成情况列出当日所有时段，问完成了吗
学生回复后收到消息识别完成/未完成 → 自动更新存档表格表格在后台可查看（学员管理内）

4.3 解答机器人 — 三层应答机制

这是AI能力体现最充分的地方，采用三层递进策略：

第一层 — 预设答案库（精准匹配）：
老师提前在知识库中上传的常见问题及答案（如"考研报名时间是什么时候"）。命中率最高，回答最准确。

第二层 — AI生成回答（大模型理解）：
如果知识库没有直接匹配，大模型基于自身知识理解问题，生成回答。适合一般性考研问题。

第三层 — AI联网搜索（实时信息）：
如果问题涉及最新政策、实时信息（如"今年XX大学分数线"），AI自动联网搜索获取最新资讯后回答。

支持的输入形式：文字、语音（转文字）、图片（OCR识别文字）、文档（PDF/Word提取内容）。

4.4 全程规划老师 — 数据整合与决策

这个机器人是整个系统的智能大脑，整合多方数据做出判断：

输入数据来源：
① 老师预设的复习路线（初始方案）
② 自测老师的测试结果（每半个月）
③ 督学机器人的完成情况（每天）
④ 解答机器人的问答记录（随时）
⑤ 刷题正确率（小程序端）

输出：
✅ 哪些知识点已经掌握了
❌ 哪些知识点还不会（薄弱环节）
📈 建议调整的复习计划
我的建议：这个机器人可以做一个"学情周报"，每周自动生成一份学生的学习报告，同步给老师和学生。内容包括本周学习时长、各科掌握度、薄弱知识点、下周建议等。

4.5 自测老师 — 出卷与监督机制

自测老师每半个月（可自定义周期）自动触发一次：

1 AI根据该学生的近期学习内容生成自测试卷（而非从题库随机抽题）
↓
2 在群内推送自测链接/试卷 → 学生在线答题
↓
3 系统自动批改客观题（AI可辅助批改主观题）
↓
4 生成成绩报告 → 同步给全程规划老师
↓
5 未按时提交 → 自动提醒 → 超过N天未交 → 通知老师人工跟进

4.6 免费答疑机器人 — 转化引擎

这是免费学员到付费学员的关键转化节点。设计上需要特别注意：

  • 回答范围限制：只能回答考研基础问题（政策、科目、流程），深度问题引导报班
  • 转化话术：回答中适当植入"这个问题在付费课程中有详细讲解"、"我们的付费学员可以享受一对一解答"等引导
  • 客服转接：如果学生表现出明确意向（如问价格、问课程），自动转接人工客服

五、数据流与系统架构建议

5.1 核心数据表关系（建议）

数据表关联关系说明
用户表→ 学员信息、权益等级（免费/体验/付费）核心用户数据
课程表→ 章节表 → 视频/资料表课程内容层级
题库表→ 题目表 → 选项表支持三种题型模式
学习计划表→ 计划时段表 → 完成记录表一对一计划存储
对话记录表→ 消息表 → 知识库匹配记录机器人对话日志
自测记录表→ 自测题目表 → 答题记录表自测数据
机器人配置表→ 机器人-群关联表机器人管理

5.2 技术架构建议

前端：小程序端使用微信原生 + WXML/WXSS；后台使用 Vue/React（PC端适配）
后端：建议使用 Node.js（NestJS）或 Python（FastAPI）作为API服务
数据库：MySQL/PostgreSQL（核心业务数据）+ Redis（缓存/队列）
AI能力：接入大模型API（如通义千问/文心一言/DeepSeek）+ Embedding模型实现知识库匹配
企业微信集成：使用企微官方API（通讯录管理+群机器人+消息推送）
文件存储：视频/资料使用对象存储（OSS/COS）
云服务：推荐腾讯云（与微信生态集成最佳）

5.3 关键数据闭环

学生学习闭环：
看课/刷题 → 产生学习数据 → 督学机器人记录完成情况 → 自测老师验证掌握度 → 全程规划老师分析→ 调整学习计划 → 回到看课/刷题

老师管理闭环：
预设计划 → 学生在群内收到计划 → 完成并反馈 → 后台查看完成情况 → 根据数据调整下一阶段计划

商业闭环：
免费学员使用刷题+答疑 → 体验专业度 → 7天体验感受全部功能 → 付费报名 → 获得一对一服务 → 口碑传播（创业板块博主）→ 带来新免费学员

六、我的设计建议与优先级

6.1 分期实施建议

考虑到开发资源，建议分三期推进：

第一期（MVP — 核心闭环打通）

目标：完成基础教学+付费+辅学闭环
包含：①直播授课 ②录播课程 ③课程分类 ④题库系统（政治选择题模式）
⑤基础学员管理 ⑥后台内容管理 ⑦简易付费功能
预计：2-3个月

第二期（AI智能服务上线）

目标：企业微信机器人和AI能力全面接入
包含：⑧免费答疑机器人 ⑨自动拉群 ⑩督学机器人 ⑪消息模板
⑫知识库管理 ⑬后台数据看板 ⑭角色权限
预计：+1.5-2个月

第三期（深度智能与扩展）

目标：全功能上线，智能分析驱动业务
包含：⑮全程规划老师 ⑯自测老师 ⑰解答机器人 ⑱择校机器人
⑲错题本 ⑳论坛社区 ㉑创业板块 ㉒个性化复习计划定制
预计：+2个月

6.2 几个关键设计要点

  • 数据打通是根基：三端必须共享同一套数据，否则机器人的判断会失准。这一点在架构设计时就要定好。
  • 知识库先行：AI机器人的效果好坏，70%取决于知识库的质量。建议在开发同时就组织老师整理常见问题和答案。
  • 消息模板灵活化：不要写死在代码里，让运营人员可以在后台随时调整话术，应对不同的营销策略。
  • 人机协作：机器人不是万能的，设计好"人工介入"的转接机制很重要。老师在群内可以随时接管对话。
  • 数据看板驱动决策：从第一天就要埋好数据点，后期才能做数据分析和智能优化。
