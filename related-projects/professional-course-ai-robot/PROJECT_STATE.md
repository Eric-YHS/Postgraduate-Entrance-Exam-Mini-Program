# 研伴 AI｜项目状态档案

> 本文件记录项目当前真实状态，不代表愿景。每次重大修改后更新。

## 项目概况

- 项目名称：研伴 AI 专业课学习与带背工具
- 项目类型：学生端 Web App + 教师端管理后台 + Python API
- 当前阶段：已部署生产环境，验收中
- 当前版本：v1.0-live-20260902
- 生产入口：`https://xiaoeduhub.online/robot/student.html`（学生端）、`https://xiaoeduhub.online/robot/teacher.html`（教师端）
- 生产形态：腾讯云 `159.75.67.99`，`/home/ubuntu/yanban-ai`，`server.py` 由 systemd 托管（`yanban-api.service`，127.0.0.1:8001），宿主机 nginx 以 `/robot/` 子路径同源反代，数据在 `/home/ubuntu/yanban-ai/data`

## 技术栈

- 前端：原生 HTML/CSS/JavaScript，`student.html`、`teacher.html`
- 后端：Python `server.py`
- 当前持久化：服务端 SQLite + `data/` 文件存储；生产首版以 Docker 持久化卷运行，后续可迁移至托管数据库与对象存储
- AI：教师端模型配置与统一角色路由；真实调用依赖外部模型 API
- 联网搜索：独立搜索服务配置（如 Tavily）；不是模型天然能力
- 部署：Docker Compose + Nginx 同源反向代理，腾讯云部署说明已提供

## 页面与入口

### 学生端

- 今日学习 / 首页：当天任务、倒计时、进度、快捷入口
- 学习内容：文本资料与考试试卷分开投喂
- 知识图谱：解析后生成可导出的结构化思维导图
- 出题训练：资料、课后题与真题驱动的训练入口
- 复习规划：基于学习时间、考试日期、资料与进度生成计划
- 带背：知识点拆解、浏览器免费语音试播、模型扩展位
- 院校画像：院校、学院、专业与考试体系分析
- 我的档案：学生基本信息、考试年份、已开通专业课
- 自测：日测、周测、月测及答案反馈

### 教师端

- 教学概览
- 学生档案与学生详情
- 学生上传资料
- 院校专业课知识管理库
- 运行监管（只读状态）
- 模型配置
- 机器人管理（动态计划、总结、自测）
- 收费配置

## 用户体系与权限

- 学生：手机号 + 密码登录，退出只清除会话 token，不清除学习数据。
- 教师：当前本地测试后台模式，负责学生账号、专业课授权、资料汇总与模型配置。
- 教师删除学生：二次确认并要求输入确认文字；删除后学生端收到已删除状态并清理该学生工作区。
- 学生端不展示模型密钥、服务地址和教师管理配置。

## AI / Agent / Robot / Tool

### 当前已实现的机器人入口

- 动态计划调整机器人
- 学习总结机器人
- 自测机器人

### 当前已实现的能力路由

- 文本：规划、资料解析、思维导图、出题、带背、批改

- 部分学习接口仍保留开发替代实现；必须由服务端真实 AI 配置后才能生成真实内容。
- 模型名称自动发现、模型删除、模型能力探测需要继续做浏览器回归验证。

## WSL 运行基线

- Ubuntu 已使用 WSL 2，G 盘项目可直接访问：
  `/mnt/g/1、专科考研/10、小程序/专业课AI机器人`。
- G 盘是唯一源码目录；不在 WSL 中复制第二份代码。
- SQLite、上传文件、文档索引和日志使用
  `/home/syt418/.local/share/yanban-ai/data`，避免在 `/mnt/g` 使用 SQLite WAL 时出现
  `disk I/O error`。
- `start-local-wsl.sh` 用 tmux 持续托管 API 与网页服务；`check-local-wsl.sh` 检查服务；
  `stop-local-wsl.sh` 只停止这两个项目会话。
- 项目目录的 `cgi.py` 是 Python 3.13+ 兼容层，保持既有浏览器 multipart 上传接口可在
  WSL Python 3.14 中运行。
