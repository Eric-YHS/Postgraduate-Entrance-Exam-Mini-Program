## 二、详细任务

### B-01 后台 10 大管理菜单框架

**需求**：将当前 admin 后台扩展为 0619 设计的 10 大菜单：
数据看板、内容管理、学员管理、题库管理、知识库/语料库、消息模板管理、论坛管理、机器人管理、创业板块、系统设置。

**现状**：`admin.html` 只有注册审核、用户管理、系统统计 3 个 Tab。

**实现建议**：
1. 重构 `admin.html` 左侧导航，按 10 大菜单组织。
2. `admin.js` 按菜单拆分渲染函数：`renderDashboard`、`renderContent`、`renderStudents`、`renderQuestions`、`renderKnowledge`、`renderMessageTemplates`、`renderForum`、`renderRobots`、`renderPromotion`、`renderSettings`。
3. 每个菜单对应独立容器，通过 hash 或按钮切换。
4. 知识库、消息模板、机器人、创业板块可先放占位页面，由 C 负责人后续填充。

**涉及文件**：`public/admin.html`、`public/admin.js`。

**验收标准**：
- admin 后台左侧显示 10 个菜单入口。
- 切换菜单显示对应功能区（已完成的先接入，未完成的显示占位提示）。

### B-02 后台内容管理

**需求**：统一管理录播、直播、免费资料、定价，后台发布 → 小程序同步。

**实现建议**：
1. 内容管理页聚合：课程列表、直播列表、网盘文件夹、免费资料。
2. 支持新建/编辑/下架课程、直播。
3. 商品资料支持设置价格、库存、是否虚拟商品、分类。
4. 操作后同步更新小程序展示状态（数据库状态字段驱动）。

**涉及表**：`courses`、`folders`、`folder_items`、`products`、`live_sessions`。

**验收标准**：
- 一个页面管理所有内容类型。
- 下架后小程序/ Web 端立即隐藏。

---

### B-03 后台学员管理（学习数据/进度）

**需求**：查看每个学员的基本信息、学习进度、完成率，上传/编辑一对一复习计划。

**实现建议**：
1. 学员列表页展示：姓名、班级、今日任务数、完成数、最近学习日期、累计做题、正确率。
2. 点击学员进入详情页：
   - 基本信息（姓名/电话/毕业院校/目标院校/当前进度）
   - 任务完成情况日历
   - 做题统计、错题分布
   - 学习周报/月报
   - 教师上传的专属复习计划
3. 新增 API：`GET /api/admin/students/:id/details`、`POST /api/admin/students/:id/plan`。
4. 专属复习计划以任务形式写入 `tasks` 表，仅 `student_ids` 包含该学生。

**涉及表**：`users`、`tasks`、`task_completions`、`practice_records`、`summaries`、`study_streaks`。

**验收标准**：
- 管理员/教师可查看任一学员完整学习档案。
- 可为单个学员制定并上传专属复习计划。

### B-04 后台题库管理

**需求**：在 admin 后台查看、编辑、删除题目，区分免费/付费可见。

**实现建议**：
1. 题库列表页：支持按科目/题型/书本/年份/难度筛选。
2. 支持编辑题目、解析、正确答案、标签。
3. 新增 `questions.is_paid_only INTEGER DEFAULT 0` 字段。
4. 学生端查询题目时根据用户权益过滤。

**涉及表**：`questions`、`question_tags`、`question_tag_relations`。

**验收标准**：
- 后台可直接维护题库。
- 付费题目对免费用户隐藏。

### B-07 管理后台数据看板

**需求**：展示学员数、活跃度、完成率、营收、学习趋势、机器人数据。

### B-08 三层权益体系（免费 / 7 天体验 / 付费）

**需求**：用户分为免费学员、新人 7 天体验、付费学员三层，功能按权益开放。

**实现建议**：
1. 新增 `user_entitlements` 表：
   - `student_id`、`tier`（`free`/`trial`/`paid`）、`trial_started_at`、`trial_ended_at`、`paid_until`（可选）。
2. 或直接在 `users` 表增加 `tier` 字段（推荐先简单实现）。
3. 新增中间件 `requireEntitlement(tiers[])`，校验当前用户权益等级。
4. 各受保护接口统一接入：直播/录播全内容、付费专区、5 大机器人、专属计划等。

**涉及表**：`users` 或 `user_entitlements`。

**验收标准**：
- 新注册用户默认 `free`，触发体验后变 `trial`，购买后变 `paid`。
- 低权益用户访问高权益接口返回 403 并提示升级。

---

### B-09 新人 7 天免费体验专区

**需求**：新注册用户 7 天内畅享全部付费功能。

**实现建议**：
1. 注册成功后自动创建体验记录，`tier='trial'`，`trial_ended_at = now + 7 days`。
2. 首页/个人中心显示体验倒计时。
3. 体验到期前 1 天推送“即将到期”提醒。
4. 到期后自动降级为 `free`，并通知用户。

**涉及表**：`user_entitlements` 或 `users`。

**验收标准**：
- 新用户注册后 7 天内可使用全部功能。
- 到期后自动降级，功能受限。

---

### B-10 付费学员专区

**需求**：付费学员享有专属每日学习计划、推送、进度提醒。

**实现建议**：
1. 教师/管理员在学员管理中可为付费学员制定专属计划（见 B-03）。
2. 督学机器人在 8:00/到点/22:00 仅对 `tier='paid'` 学员执行专属计划推送（C 负责机器人实现，B 负责权益判断与数据提供）。
3. 付费学员首页显示“专属计划”卡片。

**涉及表**：`tasks`、`users`、`notifications`。

**验收标准**：
- 付费学员收到个人专属计划推送。
- 免费/体验用户不触发专属计划推送。

---

### B-11 单科购买 / 全科打包

**需求**：付费模式为非订阅制，支持单科购买和全科打包。

**实现建议**：
1. 商品表新增 `package_type` 字段：`single_subject`、`all_subjects`、`addon`。
2. 购买单科商品后，解锁对应科目的课程/题库/直播。
3. 购买全科打包商品后，解锁全部功能。
4. 用户权益表中记录已解锁科目列表 `unlocked_subjects TEXT`。
5. 商城页面顶部增加“单科 | 全科”筛选 Tab。

**涉及表**：`products`、`orders`、`user_entitlements`。

**验收标准**：
- 用户购买单科后只能解锁对应科目内容。
- 购买全科后解锁全部内容。

---

### B-12 微信支付接入

**需求**：订单需要真实支付流程。

**实现建议**：
1. 后端接入微信支付 Native/JSAPI 下单接口（需商户号、API 证书）。
2. 新增 `POST /api/orders/:id/pay` 生成预付单，返回 `prepay_id` 等参数。
3. 小程序端调用 `wx.requestPayment` 完成支付。
4. 支付回调接口 `POST /api/wxpay/callback` 更新订单状态。
5. 订单状态从 `unpaid` → `paid` → `shipped` → `delivered` → `confirmed`。

**涉及表**：`orders`（新增 `out_trade_no`、`paid_at`）。

**验收标准**：
- 小程序可发起真实微信支付。
- 支付成功后订单状态正确流转。

---

### B-13 订单退款/售后流程

**需求**：支持退款和售后处理。

**实现建议**：
1. `orders` 表新增 `refund_status` 字段：`none`/`request`/`approved`/`rejected`/`refunded`。
2. 学生端可申请退款（未发货/虚拟商品 7 天内）。
3. 教师/管理员后台审核退款。
4. 调用微信支付退款 API。

**涉及表**：`orders`。

**验收标准**：
- 学生可申请退款，管理员可审核并执行退款。

---

### B-14 库存预警与商品搜索筛选

**需求**：库存过低提醒，商品支持搜索/筛选/排序。

**实现建议**：
1. 后台商品列表增加库存阈值设置，低于阈值标红提醒。
2. 学生端商城增加搜索框、按分类/价格排序。
3. 后端 `/api/products` 增加 `search`、`category`、`sort` 参数。

**涉及表**：`products`。

**验收标准**：
- 库存低于阈值后台提醒。
- 学生端可按分类/价格筛选商品。

---

### B-15 客服角色与权限细分

**需求**：角色体系支持超级管理员、普通老师、客服。

**实现建议**：
1. 将 `users.role` CHECK 扩展为 `('admin','teacher','customer_service','student')`。
2. 客服角色可访问学员管理、论坛管理、订单管理，但不能删除用户、修改系统设置。
3. 新增 `requireRole(['admin','customer_service'])` 等细粒度中间件。

**涉及表**：`users`。

**验收标准**：
- 可创建客服账号。
- 客服只能看到授权菜单。
